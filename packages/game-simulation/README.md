# M1 platform/combat simulation

This package owns mutable authoritative state and imports only the pure `game-project/runtime` surface. It has no renderer, clock, host APIs, storage, schema compiler, randomness source or async work. `step(world, frame)` advances one 60 Hz tick and returns events. `observe(world)` returns detached geometry in fixed units, with 256 units per logical pixel. Actor positions in observations are body top-left positions; hit, hurt and push rectangles are already in world coordinates.

The tick order is input and buffers, all eligible AI intents sampled from the same starting poses, platform/carry proposals, eligible motion, stable push separation, gathered combat contacts, trades/damage, then death/objectives and queued restart. Buffer lifetimes expire after their eligible motion so the last buffered tick remains usable. Death takes priority over a goal. An explicit restart commits last and replaces old tick events with its transition event. A hit completes its tick; participant freeze applies on the following configured ticks. New edges still enter buffers during freeze, and cancellation clears them. Other actors and platforms continue.

Unguarded damage interrupts the target execution after every gathered trade has applied. A frozen or stunned participant has no attack armor. A target in startup cannot resume that strike after hit-stop; simultaneous active strikes still damage both participants before interruption. A participant can legitimately be idle with remaining freeze/stun (a guarded victim, interrupted victim or completed attacker); timer bounds come from the enabled abilities rather than assuming idle means unfrozen.

Tile and rectangle queries visit only the swept cells/spatial buckets. Contact ties use collider IDs; movement resolves X then Y. Shapes use half-open bounds, so a side edge alone is not overlap. Gravity/scaled axis motion truncates toward zero; bucket/tile indexing floors. Carry proposals use swept actor movement and commit every rider with the platform, or retain all poses and path direction for a retry. Push separation uses stable actor IDs and the remaining actor displacement budget, so exceptionally wide push shapes can take more than one tick to separate. Self motion, carry and separation together remain within 32 pixels per coordinate per tick. Moving platforms remain within 4 pixels per tick.

`serializeCheckpoint` emits sorted canonical JSON. `restoreCheckpoint(definitions, identity, json)` validates size, depth, exact build/content/scenario/player identities, fields, collections, geometry, references, timers, ledgers and safe counter bounds into a fresh world. It rejects duplicate decoded JSON keys and negative-zero numeric tokens. Live arithmetic normalizes zero. Replace the old world only after restore returns. Before a tick consumes input, counter preflight reserves every actor's possible execution and a whole room's entity allocation; exhaustion fails without advancing input, platforms or actors. Safe terminal exhausted checkpoints remain importable, so the last committed tick always round-trips; attempting another tick fails atomically. Level replacement prepares all actors and the derived index before committing. The spatial index is rebuilt on restore.

Dead actors clear their rider contacts. Every death route records the encoded `[levelId, placementId]` tuple, and entering a previously visited room retains that defeated outcome. This small M1 ledger has a 1,024-placement ceiling with tick capacity checked before mutation; it is not a campaign save implementation. Its worst-case tuple bytes remain below the 2 MiB checkpoint import limit. Host `viewEpoch` and effects never enter authoritative bytes.

`createInputDecoder` and `decodeInputRecords` turn change-only persistent held/axis patches and ordered transient edges into complete frames. Omitted values persist; edges expire after their tick. Live frames pass through the same transition validation. Cancellation may name an already-neutral action. Releasing an action that was never held, duplicate presses, held disagreement, out-of-order sequences and more than 32 transitions per slot/tick fail before decoder mutation.

`runReplayFixture(definitions, identity, 10000, schedule?)` advances the committed semantic fixture through integer frame schedules, returning full checkpoint bytes every 1,000 ticks, final bytes and coverage counts. Alternating 300-tick runs repeat movement, combat, guard, jump, carry, freeze, restore and restart throughout the fixture. It restores active checkpoints frequently and rejects even one differing canonical byte. The fixture uses normal semantic actions and restart commands.

The shipping named scenarios contain semantic input and authored assertions: `start` traverses both rooms and wins, `second-room` proves the second room independently, `lose-and-retry` asserts death and restart, and `active-mechanics` asserts jump, attack, guard/hit-stop and carried platform state. Assertions support bounded structural JSON values, and timed scenario restart commands use the same simulation command as live play.
